The Movie Universe: Exploring Movies, People, and Audience Preferences

Dataset

Raw datasets

  • MovieLens 32M — 32,000,204 ratings and 2,000,072 free-text tags from 200,948 users, across 87,585 movies (Jan 1995–Oct 2023). grouplens.org
  • TMDB API — movie metadata (genres, budget, revenue, ratings), cast/crew credits, keywords, and user reviews, pulled per-movie via the TMDB API. developer.themoviedb.org

Processed dataset

2,914 candidate movies, built in two tracks and merged:

  • Historical (1,998 movies, 1922–2019) — selected from MovieLens by rating count, so each one has real MovieLens user-rating data (needed for the audience-similarity network below).
  • Recent (916 movies, 2016–2026) — MovieLens's ratings stop in Oct 2023 and thin out well before that for newer releases, so this track is discovered directly from TMDB (by vote count) to cover the years MovieLens can't see.

Each movie carries TMDB metadata, top-10 billed cast, director(s), and TMDB keywords. 11,481 TMDB reviews (covering ~2,650 of the 2,914 movies) were cleaned, deduplicated, and scored for sentiment.

Data cleaning / processing completed

  • Parsed release year and genre list out of MovieLens's raw title/genre strings; normalized IMDb IDs (zero-padded, since leading zeros are significant).
  • Validated and deduplicated MovieLens ratings; converted timestamps to real dates.
  • Selected the two-track candidate set described above and pulled matching TMDB records for each movie.
  • Deduplicated movies that appeared in both tracks (kept the MovieLens-linked copy) and clipped a handful of implausible TMDB budget/revenue values (crowd-edited fields occasionally carry vandalized placeholder numbers).
  • Cleaned review text (stripped HTML/URLs, dropped near-empty/duplicate reviews), scored sentiment with siebert/sentiment-roberta-large-english (chosen over a tweet-tuned model since our reviews run ~170 words at the median, far past a tweet's length), and extracted per-movie keywords via TF-IDF.

Full pipeline detail: data/README.md.

Visualizations

Visualization 2 — Audience Similarity Network

80 most-rated candidate movies, connected when a large number of MovieLens users rated both highly (≥4/5). Node size = number of connections; edge thickness = strength of the shared-audience overlap; color = primary genre. Layout is a force-directed simulation run once to a resting position (static — no interaction yet).

Interaction / Animation Plan

Visualization 2 — Audience Similarity Network

2,914 movies cleaned, but a node-link diagram is only readable up to roughly a hundred nodes shown at once — no amount of animation fixes a 2,000-node hairball. So instead of trying to render everything simultaneously, the plan is focus + search: keep the rendered view small at all times, and use interaction to make the full dataset reachable rather than all visible at once.

  • Expand the backing similarity data from today's 80 most-rated movies to all ~1,998 historical-track movies (the ones with real MovieLens ratings — the 916 "recent" movies still can't appear here, same MovieLens-coverage limit noted in the Dataset section). This is just a bigger co-rating computation, not a bigger picture.
  • Click a node to re-center the view on that movie, show only its top neighbors (fading/removing the rest), and open a detail panel with its director, top review keywords (TF-IDF, already computed in review_keywords.jsonl), and review sentiment (% positive, review count, from the sentiment model already run over all reviews in review_sentiment_summary.csv) — answers "what else do people who liked this movie also like, and why," which is the proposal's stated goal of checking whether audience similarity tracks shared genres/keywords/people, not just genre alone. Whatever the total dataset size, the screen only ever shows one movie's neighborhood.
  • Search/jump to any movie by title, not just the 80 shown by default — this is how the other ~1,900 movies stay useful: reachable on demand, not rendered up front.
  • Hover tooltip (lighter than the click panel) on a node showing title, genre, and its exact overlap counts with connected movies.
  • Drag nodes to manually untangle a crowded area.
  • Genre filter: clicking a legend entry dims nodes outside that genre, to check whether strong connections tend to stay within a genre or cross genre lines.
  • Transition animation when re-centering or jumping to a search result (nodes animate to new positions rather than snapping) so the "who's connected to whom" relationship stays legible across the change.

Evaluation Plan

What we'll evaluate: (1) whether each visualization's encodings are readable without explanation — can a first-time viewer correctly state what a node's size, color, and an edge mean; (2) whether the visualization actually helps answer the research question it's designed for (e.g., can someone use the similarity network to find a movie they'd likely enjoy, starting from one they already like); (3) whether the planned interactions above make that task noticeably easier than the static version.

How we'll evaluate it: informal think-aloud sessions with a handful of classmates/friends who weren't involved in building the project — sit them down with a specific task per visualization (e.g., "find a hidden-gem movie," "find two directors who've worked together"), watch where they hesitate or misread an encoding, and ask them to narrate their reasoning out loud. We'll do one round on the static visualizations now and a second round once interactions are implemented, to check the interactions actually closed the gaps the first round found.

What we'll collect: task success/failure and rough time-to-complete per task, notes on specific points of confusion (tied to a specific encoding or UI element, not just "confusing"), and a short 3–5 question post-task rating (clarity, usefulness, would-you-use-this-again) so feedback across sessions and rounds is comparable.
