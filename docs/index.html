The Movie Universe: Exploring Movies, People, and Audience Preferences

Dataset

Raw datasets

  • MovieLens 32M — 32,000,204 ratings and 2,000,072 free-text tags from 200,948 users, across 87,585 movies (Jan 1995–Oct 2023). grouplens.org
  • TMDB API — movie metadata (genres, budget, revenue, ratings), cast/crew credits, keywords, and user reviews, pulled per-movie via the TMDB API. developer.themoviedb.org

Processed dataset

2,914 candidate movies, built in two tracks and merged:

  • Historical (1,998 movies, 1922–2019) — selected from MovieLens by rating count, so each one has real MovieLens user-rating data (needed for the audience-similarity network below).
  • Recent (916 movies, 2016–2026) — MovieLens's ratings stop in Oct 2023 and thin out well before that for newer releases, so this track is discovered directly from TMDB (by vote count) to cover the years MovieLens can't see.

Each movie carries TMDB metadata, top-10 billed cast, director(s), and TMDB keywords. 11,481 TMDB reviews (covering ~2,650 of the 2,914 movies) were cleaned, deduplicated, and scored for sentiment.

Data cleaning / processing completed

  • Parsed release year and genre list out of MovieLens's raw title/genre strings; normalized IMDb IDs (zero-padded, since leading zeros are significant).
  • Validated and deduplicated MovieLens ratings; converted timestamps to real dates.
  • Selected the two-track candidate set described above and pulled matching TMDB records for each movie.
  • Deduplicated movies that appeared in both tracks (kept the MovieLens-linked copy) and clipped a handful of implausible TMDB budget/revenue values (crowd-edited fields occasionally carry vandalized placeholder numbers).
  • Cleaned review text (stripped HTML/URLs, dropped near-empty/duplicate reviews), scored sentiment with siebert/sentiment-roberta-large-english (chosen over a tweet-tuned model since our reviews run ~170 words at the median, far past a tweet's length), and extracted per-movie keywords via TF-IDF.

Full pipeline detail: data/README.md .

Interaction / Animation Plan

2,914 movies cleaned, but a node-link diagram is only readable up to roughly a hundred nodes shown at once — no amount of animation fixes a 2,000-node hairball. So instead of trying to render everything simultaneously, the plan is focus + search: keep the rendered view small at all times, and use interaction to make the full dataset reachable rather than all visible at once.

  • Expand the backing similarity data from today's 80 most-rated movies to all ~1,998 historical-track movies (the ones with real MovieLens ratings — the 916 "recent" movies still can't appear here, same MovieLens-coverage limit noted in the Dataset section). This is just a bigger co-rating computation, not a bigger picture.
  • Click a node to re-center the view on that movie, show only its top neighbors (fading/removing the rest), and open a detail panel with its director, top review keywords (TF-IDF, already computed in review_keywords.jsonl), and review sentiment (% positive, review count, from the sentiment model already run over all reviews in review_sentiment_summary.csv) — answers "what else do people who liked this movie also like, and why," which is the proposal's stated goal of checking whether audience similarity tracks shared genres/keywords/people, not just genre alone. Whatever the total dataset size, the screen only ever shows one movie's neighborhood.
  • Search/jump to any movie by title, not just the 80 shown by default — this is how the other ~1,900 movies stay useful: reachable on demand, not rendered up front.
  • "Recent movies like this" sidebar, shown alongside the detail panel when a node is clicked — surfaces the 916 "recent" movies (2016–2026), which have no MovieLens ratings and so can never appear as a graph node/edge here. These are ranked by content similarity instead (shared genre, shared cast/director, review-keyword overlap) rather than audience co-rating, and are deliberately kept in a separate sidebar rather than drawn as graph edges — mixing an audience-behavior edge with a content-similarity edge in the same graph would blur two different, differently-trustworthy claims ("people who liked this also liked that" vs. "this looks similar to that").
  • Hover tooltip (lighter than the click panel) on a node showing title, genre, and its exact overlap counts with connected movies.
  • Drag nodes to manually untangle a crowded area.
  • Genre filter: clicking a legend entry dims nodes outside that genre, to check whether strong connections tend to stay within a genre or cross genre lines.
  • Transition animation when re-centering or jumping to a search result (nodes animate to new positions rather than snapping) so the "who's connected to whom" relationship stays legible across the change.

Interaction / Animation Plan

For the interactive version, I plan to add several interactions that allow users to move from the overall collaboration network to more detailed information about one actor or director.

  • Search for an actor or director. Users will be able to enter a person's name and directly locate them in the network. The selected person and their direct collaborators will be highlighted while unrelated nodes are dimmed. This is useful because finding one person manually becomes difficult when the network contains hundreds of nodes.
  • Filter by movie genre. Users will be able to select a genre such as Action, Drama, Comedy, or Science Fiction. The network will then recalculate collaboration relationships using only movies from that genre. This can help users compare whether collaboration patterns change across different types of movies.
  • Change the minimum number of shared movies. A slider will allow users to increase the collaboration threshold from three shared movies to four, five, or six or more. Increasing the threshold removes weaker relationships and makes stronger repeated collaborations easier to see.
  • Select one actor or director. Clicking a person will highlight their direct collaborators and connect the collaboration network to an individual career view.
  • Explore the career view. In the career view, the x-axis will represent release year and the y-axis will represent TMDB rating. Circle size will represent movie revenue, while color will represent the movie's primary genre. This allows users to move from the overall collaboration structure to the career of one person.
  • Use hover tooltips for details. Hovering over a movie or collaboration will provide exact information without permanently adding too much text to the visualization.
  • Use transitions when the view changes. When users change the genre, collaboration threshold, or selected person, short transitions will help them follow which nodes and relationships remain instead of making the visualization change suddenly.

Interaction / Animation Plan

For the interactive version, I plan to add interactions that allow users to compare different aspects of genre performance while keeping the same genre-by-year heatmap structure.

  • Switch between different metrics. A dropdown will allow users to choose Weighted Average Rating, Total Vote Count, or Number of Movies. Keeping the same genre-by-year layout makes it easier to compare how the overall pattern changes depending on the metric.
  • Weighted Average Rating will show how highly movies in each genre–year group are rated.
  • Total Vote Count will show audience voting activity. A genre may have a high rating but relatively few votes, so this gives a different perspective from rating alone.
  • Number of Movies will show how many movies from the dataset contribute to each genre–year cell. This also helps users understand whether a rating is based on a relatively large or small group of movies.
  • Hover over a cell for exact values. The tooltip will show genre, year, weighted rating, number of movies, and total vote count. The heatmap is useful for seeing overall patterns, while the tooltip provides exact values when needed.
  • Highlight the corresponding row and column. When users hover over a cell, the selected genre row and year column will remain emphasized while unrelated cells are dimmed. This can make it easier to compare one genre across years or several genres within the same year.
  • Update the color legend when the metric changes. Since rating, vote count, and movie count have different numerical ranges, the legend will change to match the selected metric.
  • Animate metric changes. Instead of immediately replacing all colors, a short transition will show how the pattern changes when users switch between rating, voting activity, and movie count.

Evaluation Plan

What we will evaluate.
We will evaluate whether users can correctly understand the visual encodings and use each visualization to answer its intended questions. For example, in the collaboration network, users should be able to identify actors and directors and find strong repeated collaborations. In the genre heatmap, users should be able to compare rating patterns across genres and years. After interactions are implemented, we will also evaluate whether they make these tasks easier.

How we will evaluate it.
We will conduct informal think-aloud sessions with a small group of classmates or friends who were not involved in the project. Participants will complete several simple tasks using the visualizations while explaining what they are looking at and how they reach their answers. We will first test the current static versions and repeat similar tasks after the interactive features are implemented.

What data / feedback we will collect.
We will record task success or failure, approximate completion time, and specific points of confusion or misunderstanding. We will also collect short participant feedback on the clarity and usefulness of each visualization and its interactions.
